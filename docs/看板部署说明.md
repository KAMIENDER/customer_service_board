## 2. 当前发布链路

当前看板不再依赖源站公网 `80/443` 回源，也不再依赖 Let’s Encrypt 证书。

实际链路：

```text
board.jturvista.com
  -> Cloudflare DNS / Proxy
  -> Cloudflare Tunnel (jturvista)
  -> 广州服务器 cloudflared
  -> http://127.0.0.1:38888
  -> customer-service-board Node 服务
```

说明：

- 域名 HTTPS 由 Cloudflare 边缘接管。
- 源站本机服务只需要在内网监听 `127.0.0.1:38888`。
- `PUBLIC_BASE_URL` 继续使用 `https://board.jturvista.com`，知识库上传后火山回拉仍然走这个域名。

## 3. Cloudflare Tunnel 配置

当前广州服务器 `/etc/cloudflared/config.yml`：

```yaml
tunnel: 3cd286d4-b465-404a-8c2e-a9da0ccaf929
credentials-file: /etc/cloudflared/3cd286d4-b465-404a-8c2e-a9da0ccaf929.json

ingress:
  - hostname: imggen.jturvista.com
    service: http://127.0.0.1:80
  - hostname: llmapi.jturvista.com
    service: http://127.0.0.1:3333
  - hostname: board.jturvista.com
    service: http://127.0.0.1:38888
  - service: http_status:404
```

`board.jturvista.com` 绑定命令：

```bash
cloudflared tunnel route dns -f 3cd286d4-b465-404a-8c2e-a9da0ccaf929 board.jturvista.com
```

cloudflared 管理命令：

```bash
systemctl status cloudflared --no-pager
systemctl restart cloudflared
systemctl is-active cloudflared
journalctl -u cloudflared -n 200 --no-pager
cloudflared tunnel list
```

## 5. 环境变量

线上 `.env` 路径：

- `/opt/customer_service_board/.env`

当前关键项：

```bash
PORT=38888
CORS_ORIGIN=*
PUBLIC_BASE_URL=https://board.jturvista.com
VITE_KB_PROXY_BASE_URL=
```

说明：

- `PUBLIC_BASE_URL` 必须保持为 `https://board.jturvista.com`
- `VITE_KB_PROXY_BASE_URL` 为空，前端默认走同域 `/api`

## 6. DNS / 外网验证

权威 DNS 应解析到 Cloudflare 代理 IP，而不是广州服务器公网 IP。

本机验证：

```bash
dig @1.1.1.1 +short board.jturvista.com
dig @8.8.8.8 +short board.jturvista.com
```

当前预期会返回 Cloudflare 代理 IP，例如：

```text
172.67.129.185
104.21.2.217
```

从广州服务器公网回环验证：

```bash
curl -I https://board.jturvista.com
curl -s https://board.jturvista.com/api/health
```

预期：

- 首页返回 `HTTP/2 200`
- `/api/health` 返回 JSON
